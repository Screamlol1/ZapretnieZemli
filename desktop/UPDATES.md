# Обновления и восстановление Windows-версии

Настройки → «Обновления». Проверка выполняется вручную и обращается к последнему публичному стабильному выпуску `Screamlol1/ZapretnieZemli`. Если выпусков ещё нет, приложение сообщает об этом явно. Разработка и запуск своего сервера работают без GitHub.

Установщик принимается только из этого репозитория: версия должна быть новее установленной, имя соответствовать версии и архитектуре x64, размер — объявленному размеру, SHA-256 — полю `digest` GitHub Release Assets. Проверка повторяется непосредственно перед запуском. Перенаправления допускаются только на адреса раздачи файлов GitHub по HTTPS. Непроверенная или незавершённая загрузка не запускается.

Загрузка не прерывает игру. Кнопка установки доступна после проверки файла; установка работает только в установленном приложении. Открытые редакторы необходимо сохранить или закрыть. После подтверждения приложение делает согласованную SQLite-копию через свой сервер, записывает сведения о переходе версии, останавливает свой сервер и запускает NSIS. Ошибка создания копии блокирует установку. Данные лежат вне папки программы и не удаляются при обновлении.

Копии находятся в `%LOCALAPPDATA%/ZapretnieZemli/update-backups`. Кнопка «Восстановить из копии» принимает папку с `COMPLETE.json`: проверяет пути, SHA-256 всех файлов и целостность SQLite. Перед заменой автоматически создаётся ещё одна копия текущих данных. Восстанавливаются все локальные аккаунты и кампании, пользовательские карты и локальная подложка мира. Настройки окна и профиль браузера остаются отдельными. Восстановление требует повторного входа при истёкшей сессии; новую ссылку приглашения следует создать заново.

Это восстановление данных, а не автоматический откат исполняемой программы. Для возврата к предыдущей программе используется её сохранённый установщик и совместимая резервная копия. Книги, пользовательские базы и файлы копий не входят в исходный архив или установщик.

## Публикация следующей версии

1. Изменить `desktop/package.json` и lockfile, выполнить проверки и подготовить коммит.
2. Создать тег `desktop-vX.Y.Z`, совпадающий с версией пакета.
3. Workflow `windows-build.yml` запускает правила, сервер, браузер, проверки настольного приложения, собирает установщик и только после успеха публикует GitHub Release с установщиком и SHA256SUMS.

Обычный push и ручная сборка без тега не публикуют выпуск. Существующий выпуск автоматически не перезаписывается. Приложение не загружает произвольный URL, не получает токены GitHub и не отправляет игровые данные на сервер обновлений.
