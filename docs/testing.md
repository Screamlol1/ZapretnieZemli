# Проверки игры и сборка Windows

Команды выполняются в каталоге с `server.py` и `package.json`: в рабочем пространстве это `game/`, а в опубликованном репозитории — его корень. Workflow в `.github/workflows/` рассчитаны именно на такой корень публикации.

## Установка

Нужны Node.js 22 или 24 и Python 3.11+. У браузерных тестов нет зависимости от Edge, установленной игры, пользовательской базы или файлов в каталоге Codex.

```sh
npm ci
npx playwright install chromium
```

На Linux для установки системных библиотек браузера:

```sh
npx playwright install --with-deps chromium
```

Закреплён `@playwright/test` 1.64.1 и соответствующая версия Chromium; `package-lock.json` фиксирует зависимости. Версия сверена с официальным npm registry 1 ноября 2026 года. Инструкции по установке и обновлению: [Playwright](https://playwright.dev/docs/intro), [браузеры](https://playwright.dev/docs/browsers), [пакет npm](https://www.npmjs.com/package/@playwright/test).

## Быстрые проверки

```sh
npm test
python -m unittest discover -s tests -v
npm run test:desktop
npm run test:e2e
```

`test:desktop` запускает тесты политик и настроек Electron. Проверки встроенного Windows runtime автоматически пропускаются, если нет Windows или ещё не установлен runtime; отдельный Windows workflow устанавливает его и запускает эти проверки полностью.

`test:e2e` запускает восемь браузерных сценариев в Chromium, по два параллельно:

- Регистрация, глазик пароля, создание и изменение сохранённого листа.
- Создание героя игроком в кампании, владение листом и отказ от несохранённых изменений.
- Восстановление локального черновика и боевая песочница без новых окон.
- Кабинет, настройки и лист на экране шириной 390 пикселей.
- Общий бросок трём участникам, отдельные штрафные кости, артефактные кости и скрытые броски Мастера.
- Общая атмосфера и звуки, локальная проба, личное отключение звука и отсутствие повторов.
- Сохранение кампании и восстановление владельца после перезапуска тестового сервера.
- Поворот, перемещение и отмена в редакторе локации, публикация игроку и экспорт SVG.

Каждый тест получает новую временную папку, пустой SQLite и свободный порт, назначенный ОС. Приватные карты и рабочая база не подключаются. Вспомогательный Python-сервер закрывается через stdin, в том числе при прекращении родительского процесса; после теста временные данные удаляются. Тесты не используют порт 8789.

Python выбирается из переменной `PYTHON`, затем из `python3`/`python` в `PATH`, а на Windows также проверяется `py -3`. `PYTHON` должна содержать только путь к исполняемому файлу, без дополнительных аргументов. Пример PowerShell:

```powershell
$env:PYTHON = 'C:\Python312\python.exe'
npm run test:e2e
```

Node для серверных правил берётся из процесса, запустившего Playwright (`ZZ_NODE=process.execPath`). Все пути передаются массивами аргументов, поэтому пробелы и кириллица не требуют ручного экранирования.

## Отчёты и отладка

```sh
npm run test:e2e:report
npm run test:e2e:ui
npm run test:e2e -- e2e/multiplayer.spec.js
npm run test:e2e -- --headed --workers=1
```

HTML-отчёт находится в `playwright-report/index.html`. При ошибке в `test-results/` остаются trace, снимки экранов всех участников, видео и журнал изолированного сервера. Trace открывается командой `npx playwright show-trace <путь-к-trace.zip>`. Эти папки исключены из Git, но сохраняются артефактами CI. В отчётах могут быть пароли и приглашения автоматически созданных тестовых аккаунтов; их сервер и база удаляются после сценария.

Старые исследовательские сценарии в родительском `work/` не изменены. Они не являются переносимым CI-набором и могут зависеть от локальных путей и Edge.

## Нативная проверка Windows

В Windows можно проверить настоящее окно Electron, сохранение его режима, редактор во встроенном представлении и совместную игру с браузером:

```sh
npm --prefix desktop ci
npm --prefix desktop run prepare:runtime
npm run test:e2e:desktop
```

Этот тест запускается отдельно от обычного Chromium-набора, создаёт временный профиль через `--zz-data-dir` и не обращается к сохранениям установленной игры. Он открывает настоящее окно. Отчёт: `playwright-desktop-report/index.html`; при ошибке — trace Electron и снимок оболочки в `test-results-desktop/`. На других ОС сценарий явно пропускается.

## CI и установщик

`tests.yml` выполняет правила, Python и desktop unit tests в Ubuntu/Windows. В Ubuntu устанавливается FFmpeg, чтобы тесты обработки аудио проверяли реальное преобразование файлов; отдельная задача Ubuntu устанавливает закреплённый Chromium и выполняет браузерные сценарии. Отчёты хранятся 14 дней.

`windows-build.yml` запускается вручную или по тегу `v*`/`desktop-v*`. Он проверяет правила, сервер, браузерные сценарии, встроенные runtime и нативный Electron-сценарий, затем собирает NSIS. В артефакт на 30 дней попадают установщик и `SHA256SUMS.txt`. GitHub Release автоматически не создаётся: сборка использует `--publish never` и права `contents: read`.

Локальная сборка теми же командами:

```sh
npm --prefix desktop run prepare:runtime
npm --prefix desktop run dist -- --publish never
```

Текущая конфигурация electron-builder пишет установщик в `../outputs/windows` относительно корня опубликованного репозитория. Изменять версию приложения нужно отдельно в desktop-пакете. Зелёный локальный запуск не подтверждает работу GitHub Actions: результат удалённого CI проверяется после фактического запуска workflow.
